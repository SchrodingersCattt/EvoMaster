Two changes to break the circular import:

**Change 1: matmaster/assembly/exp.py**
- Remove the top-level import `from matmaster.engine.agent import AgentKernel` (line 14)
- Add a `TYPE_CHECKING` block at the top for type annotation usage:
  ```python
  from __future__ import annotations
  from typing import TYPE_CHECKING
  if TYPE_CHECKING:
      from matmaster.engine.agent import AgentKernel
  ```
- Inside the `run()` method body, add a lazy import before using AgentKernel:
  ```python
  def run(self, ctx, task, *, stop_event=None, **assemble_kwargs):
      spec = self.assemble(ctx, **assemble_kwargs)
      from matmaster.engine.agent import AgentKernel  # lazy import to avoid circular
      kernel = AgentKernel()
      return kernel.run(spec, task, stop_event=stop_event)
  ```
- Keep all other imports unchanged (PlaygroundContext, FinishEvent, AgentRuntimeSpec)

**Change 2: matmaster/assembly/__init__.py**
- Move imports of `Exp` and `DirectExp` into a lazy import pattern using a module-level `__getattr__` function
- Keep direct imports of ToolRegistry, Tool, ContextBuilder, WorkerRegistry, ManuscriptGateGuard, AuthFailureGateGuard (these do NOT trigger the circular chain)
- Add `__getattr__` function that lazily imports Exp/DirectExp on first access:
  ```python
  def __getattr__(name: str):
      if name == "Exp":
          from .exp import Exp
          return Exp
      if name == "DirectExp":
          from .direct_exp import DirectExp
          return DirectExp
      raise AttributeError(f"module {__name__!r} has no attribute {name!r}")
  ```
- Keep `__all__` unchanged (all 8 symbols still listed) so that `from matmaster.assembly import DirectExp` still works -- it just triggers lazy loading instead of eager loading
- Remove the top-level `from .direct_exp import DirectExp` and `from .exp import Exp` lines

This approach: (a) breaks the circular chain because assembly package init no longer eagerly imports exp.py/direct_exp.py, (b) preserves all public API (any code doing `from matmaster.assembly import DirectExp` still works), (c) keeps type checking support via TYPE_CHECKING block.
