具体要求：
1. 删除 `import queue` 和 `ReplyQueueLike` Protocol，hook 文件不再保留 `reply_queue.get()` 路径。
2. 使用 `import asyncio`，在 `ConfirmationHook.__init__()` 中保留这些字段：
   - `self._bus`
   - `self._timeout_sec`，类型改为 `float`，默认值 `20`
   - `self._confirm_tools`
   - `self._source`
   - `self._loop: asyncio.AbstractEventLoop | None = None`
   - `self._pending_future: asyncio.Future[str | None] | None = None`
3. `__init__()` 签名恢复为只接收 `bus`、`timeout_sec`、`confirm_tools`、`source`，不要再出现 `reply_queue` 参数。
4. 添加 `set_loop(self, loop: asyncio.AbstractEventLoop) -> None`，供 kernel 的 `hasattr(hook, "set_loop")` 注入当前运行 loop。
5. 将 `pre_tool_call()` 改为 `async def`，逻辑必须是：
   - `self._loop is None` 时直接 `CONTINUE`
   - `confirm_tools` 非空且 `tool_call.name` 不在集合中时直接 `CONTINUE`
   - 通过 `await self._bus.emit(ConfirmationRequestEvent(...))` 发出确认事件，不要用 `emit_nowait()`，因为当前 hook 已运行在 async kernel 内
   - `timeout_seconds` 传给 `ConfirmationRequestEvent` 时使用 `int(self._timeout_sec)`，保持事件模型字段类型兼容
   - 通过 `future = self._loop.create_future()` 建立 pending future，并 `await asyncio.wait_for(future, timeout=self._timeout_sec)`
   - `finally` 中清空 `self._pending_future = None`
   - 超时和 cancel 都返回 `HookAction.SKIP`
6. 恢复 `resolve(self, reply: str)` 与 `cancel(self)` 两个公开接口，二者都必须：
   - 先执行 atomic swap：读取 `future = self._pending_future` 后立即 `self._pending_future = None`
   - 如果 future 为 `None`、已完成、或 loop 不可用则直接返回
   - 用 `self._loop.call_soon_threadsafe(...)` 安全设置结果
   - `cancel()` 把 future 结果设为 `None`
7. 不要修改 `matmaster/core/agent.py`，除非你发现当前 `hook.set_loop(loop)` 路径已经不存在。当前代码已满足 loop 注入契约，本 task 只恢复 hook 本身。
8. 文档字符串要更新为当前事实：
   - 说明 hook 基于 `asyncio.Future`
   - 说明外部线程通过 `resolve()` / `cancel()` 注入结果
   - 不要再描述 `queue.Queue.get()` 阻塞模型

如果你参考 `git show 70521e2:matmaster/hooks/confirmation.py`，必须显式修正其中与当前主干不兼容的一点：`ConfirmationRequestEvent` 的发射在当前代码上应写成 `await self._bus.emit(...)`，而不是直接调用未 await 的 `bus.emit(...)`。
