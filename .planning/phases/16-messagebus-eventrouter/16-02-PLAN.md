    CRITICAL: Wrap the entire router loop lifecycle in try/finally to prevent thread/loop leaks on exceptions (per CLAUDE.md: service layer does not swallow exceptions).

    Before the router.start() call (~line 301), create a bridge loop with exception-safe cleanup:
    ```python
    import asyncio
    _router_loop = asyncio.new_event_loop()
    _router_loop_thread = threading.Thread(target=_router_loop.run_forever, daemon=True, name="router-loop")
    _router_loop_thread.start()
    try:
        _sync_call_async(router.start(), _router_loop)
        # ... existing run_agent logic ...
    finally:
        try:
            _sync_call_async(router.stop(), _router_loop)
        except Exception:
            logger.warning("router.stop() failed during cleanup", exc_info=True)
        _router_loop.call_soon_threadsafe(_router_loop.stop)
        _router_loop_thread.join(timeout=5)
    ```

    The try/finally ensures that even if run_agent raises an unexpected exception, the router loop thread is always stopped and joined. The inner try/except around router.stop() prevents stop() failures from masking the original exception (per CLAUDE.md: service layer degrades gracefully).

    NOTE: The router's asyncio.Task consume loop runs in _router_loop. MessageBus operations (put_nowait in emit/emit_nowait, get in consume_loop) are safe because put_nowait is sync and get runs inside the same _router_loop.
