```python
class MessageBus:
    def set_loop(self, loop: asyncio.AbstractEventLoop) -> None:
        """Capture event loop for thread-safe emit_nowait."""
        self._loop = loop

    async def emit(self, event: BusEvent) -> None:
        """Async emit (put_nowait internally). Call from within event loop."""
        self._queue.put_nowait(event)

    def emit_nowait(self, event: BusEvent) -> None:
        """Thread-safe sync emit. Uses call_soon_threadsafe when loop is set."""
        if self._loop is not None and self._loop.is_running():
            self._loop.call_soon_threadsafe(self._queue.put_nowait, event)
        else:
            self._queue.put_nowait(event)

    async def get(self, timeout: float | None = None) -> BusEvent: ...
    def get_nowait(self) -> BusEvent: ...
```

<review_concerns>
## Cross-AI Review Concerns Addressed in This Plan

1. **Loop ownership / _sync_call_async conflict (HIGH, consensus)** -- The old plan used _sync_call_async(router.start(), _router_loop) which calls run_until_complete. But _router_loop runs run_forever() in a daemon thread, making run_until_complete fail with "event loop already running". Fix: use asyncio.run_coroutine_threadsafe(router.start(), _router_loop).result() which is designed for exactly this pattern -- scheduling a coroutine on a loop running in another thread.

2. **Handler dispatch order (Codex)** -- Reorder handler list: SSEHandler first, then PersistenceHandler. Serial dispatch means SSEHandler (fast async send) runs before PersistenceHandler (slower to_thread DB write), reducing frontend latency.

3. **Service finally cleanup order (Codex)** -- Ensure bohrium_svc.cleanup() runs before router.stop(), because cleanup can still emit events via _bohrium_event_cb. After bohrium cleanup, stop router to drain final events.
</review_concerns>

    **Category B: Router lifecycle -- dedicated loop with run_coroutine_threadsafe**
    This is the CRITICAL structural fix addressing review concern #2.

    The old plan used `_sync_call_async(router.start(), _router_loop)` which calls `loop.run_until_complete(coro)`. But router's asyncio.Task needs a loop running `run_forever()` (otherwise create_task has no running loop). You CANNOT call run_until_complete on a loop already doing run_forever.

    Correct pattern: create a dedicated daemon thread running `loop.run_forever()`, then use `asyncio.run_coroutine_threadsafe(coro, loop).result()` to schedule coroutines from the service thread. This is the standard asyncio cross-thread pattern.

    Implementation in run_agent_sync, BEFORE the EventRouter constructor:

    ```python
    import threading

    # Create dedicated event loop for router's async task.
    # Router's consume loop (asyncio.Task) runs in this loop.
    # Service layer communicates via run_coroutine_threadsafe.
    _router_loop = asyncio.new_event_loop()
    _router_loop_thread = threading.Thread(
        target=_router_loop.run_forever,
        daemon=True,
        name="router-loop",
    )
    _router_loop_thread.start()
    ```

    Change router.start() call:
    ```python
    # OLD: router.start()
    # NEW: schedule on router loop, wait for completion
    asyncio.run_coroutine_threadsafe(router.start(), _router_loop).result()
    ```

    Change the finally block for router cleanup. IMPORTANT: addresses review concern about cleanup order -- bohrium cleanup can still emit events, so it MUST run before router.stop():

    ```python
    finally:
        # ... existing logging ...

        # Bohrium cleanup FIRST -- it can still emit events via _bohrium_event_cb
        if bohrium_svc:
            try:
                bohrium_svc.cleanup(
                    session_id=session_id,
                    event_callback=_bohrium_event_cb,
                    pg_for_run=playground if 'playground' in dir() else None,
                    ssh_attached=ssh_attached,
                )
            except Exception:
                logger.warning('Bohrium cleanup error', exc_info=True)

        # Exp cleanup
        if exp:
            try:
                exp._run_cleanup_callbacks()
            except Exception:
                logger.warning('Exp cleanup error', exc_info=True)

        # Router stop LAST -- drains any final events from bohrium cleanup
        if router:
            try:
                asyncio.run_coroutine_threadsafe(
                    router.stop(), _router_loop
                ).result(timeout=10)
            except Exception:
                logger.warning('router.stop() failed during cleanup', exc_info=True)

        # Shut down the dedicated router loop
        _router_loop.call_soon_threadsafe(_router_loop.stop)
        _router_loop_thread.join(timeout=5)

        # ... remaining cleanup (Redis, playground release, gc) ...
    ```

    The try/except around router.stop() prevents stop() failures from masking the original exception. The _router_loop.stop() + thread.join() ensures the daemon thread is cleaned up even on crash. timeout=5 on join prevents indefinite hang.
