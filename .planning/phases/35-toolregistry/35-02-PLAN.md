<objective>
启用 ToolBinding 的 state_mode/stop_mode 字段：ToolCompiler 根据工具元数据填充，FullToolRunner 根据 stop_mode 调整取消策略。

Output: BUILTIN_STOP_MODES 映射表在 tool_compiler.py 中定义，FullToolRunner cancel check 根据 stop_mode 区分行为。
</objective>

    **Step 1: FullToolRunner cancel check 扩展 (matmaster/core/tool_runner.py)**
    在 execute_batch() 方法中找到 cancel check（约 L259，当前为 `if ctx.stop_event is not None and ctx.stop_event.is_set()`）。

    当前逻辑是：stop_event 被设置时，对所有工具无条件返回 cancelled ToolResult。需要改为根据 instance.tool_binding.stop_mode 区分：

    修改 cancel check 逻辑（在 per-tool 循环内部，catalog lookup 之后、Scheduler acquire 之前）：
    ```python
    # Step 1: Cancel check (stop_mode-aware)
    if ctx.stop_event is not None and ctx.stop_event.is_set():
        stop_mode = instance.tool_binding.stop_mode
        if stop_mode == "cancellable":
            tr = ToolResult(status="cancelled", content="Run cancelled.")
            results.append((tc, tr))
            if on_result:
                on_result(tc, tr)
            continue
        elif stop_mode == "best_effort":
            tr = ToolResult(
                status="cancelled",
                content="Cancellation requested (best-effort). Tool may have partially completed.",
            )
            results.append((tc, tr))
            if on_result:
                on_result(tc, tr)
            continue
        # stop_mode == "non_cancellable": skip cancel check, let tool execute
    ```

    注意：FullToolRunner 中有两处 cancel check（L114 是 batch 级别的快速检查，L259 是 per-tool 级别）。L114 处不需要 stop_mode 感知（那是在 catalog lookup 之前，还没有 instance）。L259 处需要改造（已有 instance）。

    实际上根据 RESEARCH，更准确的位置是在 _execute_single 或 per-tool 循环中 catalog.get_tool() 之后。请仔细读取 tool_runner.py 确认具体位置。
