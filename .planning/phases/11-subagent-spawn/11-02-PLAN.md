    **Critical design decision for stop_event propagation (Research Open Question #1/#3):**

    The service layer calls `build_runtime()` then separately passes `stop_event` to `kernel.run()`. The spawn_fn closure needs stop_event to pass to child kernel.run(). Two approaches were analyzed in RESEARCH.md.

    **Chosen approach:** spawn_fn closure captures a mutable container `[None]` for stop_event. Exp.run() sets it before kernel.run(). For service-layer callers (agent_run_service.py), SubAgentTool receives stop_event via a `set_stop_event(event)` method that updates the closure's reference. This is implemented by making `_make_spawn_fn` return both the spawn_fn and a setter.

    Actually, the SIMPLEST correct approach: spawn_fn does NOT capture stop_event. Instead, SubAgentTool stores `_stop_event` attribute, and spawn_fn reads `SubAgentTool._stop_event` at call time. But spawn_fn is a closure, not a method on SubAgentTool.

    **Final chosen approach (cleanest):** The spawn_fn closure captures a `stop_event_ref: list[threading.Event | None]` (a mutable list of one element). `_make_spawn_fn` returns `(spawn_fn, stop_event_ref)`. The Exp stores the ref. In `Exp.run()`, before calling `kernel.run()`, set `stop_event_ref[0] = stop_event`. For service-layer callers, expose a method `set_spawn_stop_event(event)` on Exp that does the same. OR: add the SubAgentTool instance to a list on Exp, and before kernel.run in service layer, iterate and set `tool._stop_event = stop_event`.

    **ACTUALLY, the simplest approach that requires zero changes to agent_run_service.py:** In build_runtime, after registering SubAgentTool, store a reference to it on the AgentRuntime or return it. The service layer does NOT need to know about stop_event propagation at all -- the SubAgentTool can obtain stop_event from the **same shared threading.Event** that the service layer passes to kernel.run. BUT SubAgentTool.execute() is called by the kernel during tool execution, and the kernel already has stop_event.

    **CORRECT FINAL APPROACH:** The simplest pattern consistent with the codebase. spawn_fn captures a mutable list `_stop_ref = [None]` as its stop_event source. Exp adds a method or stores the ref. In `Exp.run()`, set `_stop_ref[0] = stop_event` before kernel.run. For the service layer path (agent_run_service.py), the service layer does NOT call Exp.run() -- it calls build_runtime() + kernel.run() separately. So we need to expose the stop_ref on the returned AgentRuntime or SubAgentTool.

    **Implementation: store stop_ref on SubAgentTool directly.** spawn_fn reads `sub_agent_tool._stop_event` at call time. In `Exp.run()`, iterate spec.tool_registry for SubAgentTool instances and set `._stop_event = stop_event` before kernel.run. In service layer, add one line after build_runtime: iterate and set stop_event the same way. This is clean, explicit, and matches the ReadTracker cleanup pattern.

    **BUT WAIT -- actually the service layer should NOT need changes.** The service layer passes stop_event to kernel.run(). Inside kernel.run(), when SubAgentTool.execute() is called during tool dispatch, SubAgentTool needs stop_event. If we pass stop_event into the spawn_fn closure at creation time, we'd need the ref trick. If instead we make spawn_fn a method on a small object that holds a mutable stop_event, we can set it.

    **FINAL DECISION:** Keep it simple. Use the mutable-container pattern inside spawn_fn. `_make_spawn_fn` returns `(spawn_fn, stop_event_holder)` where `stop_event_holder` is `{"event": None}`. Spawn_fn reads `stop_event_holder["event"]` at call time. Store `stop_event_holder` as `self._spawn_stop_holder`. In `Exp.run()`, set `self._spawn_stop_holder["event"] = stop_event` before kernel.run. For service-layer direct usage, add a one-line helper `Exp.set_spawn_stop_event(event)` or document that callers set it on the returned runtime.

    Since AgentRuntime is frozen, we can't add attributes. But we CAN add a method to Exp. The service layer already holds the `exp` instance (line 315). So after build_runtime, before kernel.run, service layer would call `exp.set_spawn_stop_event(stop_event)`.

    **A. Add `_make_spawn_fn` static method to Exp:**

    ```python
    @staticmethod
    def _make_spawn_fn(
        ctx: PlaygroundContext,
        bus: MessageBus | None,
        source_prefix: str,
    ) -> Callable[[str, str, threading.Event | None], str]:
        def spawn_fn(exp_name: str, task: str, stop_event: threading.Event | None = None) -> str:
            from matmaster.config.loader import load_exp_config
            child_config = load_exp_config(exp_name)
            child_exp = Exp(child_config)
            child_source = f"{source_prefix}:{exp_name}"
            child_runtime = child_exp.build_runtime(ctx, bus=bus, source_override=child_source)
            try:
                run_result = child_runtime.kernel.run(
                    child_runtime.spec, task, stop_event=stop_event
                )
                result = run_result.result
                if result.status == "completed" and result.final_content:
                    return result.final_content
                return f"SubAgent finished with status={result.status}, reason={result.reason}"
            finally:
                child_runtime.cleanup()
        return spawn_fn
    ```
