**matmaster/core/exp.py -- _make_spawn_fn async 闭包 (per D-04)：**

当前 `_make_spawn_fn` (line 89-133) 返回 sync `spawn_fn` 内含 bridge loop，且手动调用 build_runtime + kernel.run + cleanup。

**Key design decision: spawn_fn 复用 Exp.run().** 新的 async spawn_fn 将调用 `await child_exp.run(ctx, task, ...)` 而非手写 build_runtime + kernel.run + cleanup 流程。理由：
- Exp.run() 已经封装了完整的生命周期（build_runtime -> kernel.run -> cleanup），包括 try/finally 保证 cleanup
- 避免在 spawn_fn 中重复 Exp.run() 内部的逻辑（stop_event injection、cleanup 保证等）
- 满足 roadmap success criteria: "async spawn_fn -> await child Exp.run() -> await child kernel.run()"

**Addresses review concern (source_override/spawn_id keyword-only):** Exp.run() 添加 `source_override` 和 `spawn_id` 可选参数。这两个参数只服务于 event source 和 spawn tracing，不是给普通调用方使用的业务参数。保持 keyword-only 以防止位置参数误用。

2. **_make_spawn_fn 改造：**

```python
@staticmethod
def _make_spawn_fn(
    ctx: PlaygroundContext,
    bus: MessageBus | None,
    source_prefix: str,
) -> Any:
    """Create async spawn_fn closure capturing parent runtime context.

    The returned async callable creates a child Exp from exp_name,
    runs it via child_exp.run() with the parent's PlaygroundContext
    and MessageBus, and returns the result text.

    Parameters source_override and spawn_id are forwarded to
    child_exp.run() for event source tracing only -- they are
    internal spawn chain parameters, not general-purpose API.
    """

    async def spawn_fn(
        exp_name: str,
        task: str,
        stop_event: threading.Event | None = None,
    ) -> str:
        from matmaster.config.loader import load_exp_config

        child_config = load_exp_config(exp_name)
        child_exp = Exp(child_config)
        child_source = f"{source_prefix}:{exp_name}"
        child_spawn_id = uuid.uuid4().hex[:16]
        result = await child_exp.run(
            ctx,
            task,
            bus=bus,
            stop_event=stop_event,
            source_override=child_source,
            spawn_id=child_spawn_id,
        )
        if result.status == "completed" and result.final_content:
            return result.final_content
        return f"SubAgent finished with status={result.status}, reason={result.reason}"

    return spawn_fn
```

关键变化：
- `def spawn_fn` -> `async def spawn_fn`
- 移除手动 build_runtime + kernel.run + cleanup 流程，替换为单个 `await child_exp.run(...)`
- Exp.run() 内部已经有 try/finally 保证 cleanup，spawn_fn 不再需要自己管 cleanup
- 删除 `_loop = asyncio.new_event_loop()` / `_loop.close()` bridge
- `child_exp.run()` 返回 KernelResult（不是 KernelRunResult），其 .status 和 .final_content 可直接访问
- history=None 不传给 child（child 不应继承 parent history）

**Addresses review concern (_make_spawn_fn return type):** `_make_spawn_fn` 返回 `Any` 而非精确的 async callable 类型。理由：Python 标准 Callable 不区分 sync/async。如果要精确表达，需要 `Callable[[str, str, threading.Event | None], Coroutine[Any, Any, str]]`，但这在 runtime 不可检查且可读性差。`Any` 配合 docstring 说明是合理的折中。

```python
async def execute(self, arguments: dict[str, Any]) -> str | ToolResult:
    """Override BuiltinTool.execute() for native async spawn.

    SpawnTool is the only BuiltinTool that needs native async execution
    (spawn_fn is async). Bypasses the base class to_thread(_execute) pattern.
    Preserves the full error contract: recursion guard, validation, exception catch.
    """
    if self._spawn_fn is None:
        return (
            "Error: Spawn is not available in this context "
            "(recursion depth limit reached)"
        )

    exp_name = arguments.get("exp_name", "").strip()
    task = arguments.get("task", "").strip()

    if not exp_name or not task:
        return "Error: Both exp_name and task are required"

    try:
        return await self._spawn_fn(exp_name, task, self._stop_event)
    except Exception as e:
        self.logger.error("Tool %s failed: %s", self.name, e, exc_info=True)
        return f"Error: {e}"
```
