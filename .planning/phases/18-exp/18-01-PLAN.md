**matmaster/core/exp.py -- 4 个方法签名改造 + bridge 移除：**

1. 添加 `import inspect` 到 imports（已有 asyncio, logging, threading, uuid 等）。

2. `__init__` (line 52-55): 更新 `_cleanup_callbacks` 类型注解从 `list[Callable[[], None]]` 为 `list[Callable[[], Any]]`（兼容 sync 和 async callback）。`Any` 已从 typing 导入。

   **Addresses review concern (cleanup type):** 使用 `Callable[[], Any]` 而非更精确的类型别名。理由：Python typing 对 async callable 的表达能力有限，`Callable[[], Awaitable[None]] | Callable[[], None]` 在 runtime 不可 isinstance 检查。`CleanupCallback` 类型别名可在 Phase 19 引入，当前 `Any` 是最简方案，且 mypy 不会误报。

3. `_register_cleanup` (line 66-68): 参数类型从 `Callable[[], None]` 改为 `Callable[[], Any]`。

4. `_run_cleanup_callbacks` (line 70-85): 改为 `async def _run_cleanup_callbacks(self) -> None:`。内部循环改为双重检测 async callback -- 先用 iscoroutinefunction 检查，回退到 isawaitable 检查结果（per D-02, addresses review concern: iscoroutinefunction 对 partial/decorator 不稳，增加 isawaitable 兜底）：
```python
async def _run_cleanup_callbacks(self) -> None:
    for cb in self._cleanup_callbacks:
        try:
            if inspect.iscoroutinefunction(cb):
                await cb()
            else:
                result = cb()
                if inspect.isawaitable(result):
                    await result
        except Exception:
            self.logger.warning(
                "Cleanup callback %s raised, continuing with remaining callbacks",
                cb,
                exc_info=True,
            )
    self._cleanup_callbacks.clear()
```

5. `assemble` (line 137-145): 改为 `async def assemble(self, ctx: PlaygroundContext) -> AgentRuntimeSpec:`。函数体不变（纯数据转换，无 I/O）。Per D-01/EXPL-01。

6. `build_runtime` (line 149-250): 改为 `async def build_runtime(self, ctx, ...) -> AgentRuntime:`。内部第一行 `spec = self.assemble(ctx)` 改为 `spec = await self.assemble(ctx)`。其余函数体不变（所有 helper 调用都是 sync）。Per D-01/EXPL-02。

7. `run` (line 274-305): 改为 `async def run(self, ctx, task, ...) -> KernelResult:`。Per D-06/EXPL-03。

**CRITICAL (addresses review concern: build failure cleanup guarantee): try/finally 必须从 build_runtime 开始。** build_runtime 内部已经通过 _register_cleanup 注册了 tracker.clear 和 connector.cleanup。如果 build_runtime 成功但 kernel.run 抛错，或者 build_runtime 部分成功后抛错，cleanup 都必须执行。实现：

```python
async def run(self, ctx, task, *, bus=None, history=None, stop_event=None, skills=None, mcp=None) -> KernelResult:
    """build_runtime -> kernel.run -> cleanup."""
    try:
        runtime = await self.build_runtime(ctx, bus=bus, skills=skills, mcp=mcp)
        # Inject stop_event into SpawnTool for cancel propagation (SUBA-05)
        tool_registry = getattr(runtime.spec, "tool_registry", None)
        if stop_event is not None and tool_registry is not None:
            from matmaster.tools.builtin.spawn_tool import SpawnTool
            for tool in tool_registry.all_tools:
                if isinstance(tool, SpawnTool):
                    tool._stop_event = stop_event
        result = await runtime.kernel.run(
            runtime.spec, task, history=history, stop_event=stop_event
        )
        return result.result
    finally:
        await self._run_cleanup_callbacks()
```

与旧代码对比: 旧代码的 finally 只调 `runtime.cleanup()`，如果 build_runtime 本身抛错，runtime 未定义，会触发 NameError 掩盖原始错误。新代码的 finally 直接调 `await self._run_cleanup_callbacks()` -- 即使 build_runtime 失败，_cleanup_callbacks 列表可能为空或有部分注册的 callback，_run_cleanup_callbacks 安全执行。
