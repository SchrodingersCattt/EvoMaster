# GPUMD Installation and Runtime Reference

Official source: https://gpumd.org/installation.html

## Runtime Scope

GPUMD is written in CUDA C++ and is intended for Nvidia GPUs. The official docs
state that compiling and running GPUMD require:

- Nvidia GPU with compute capability >= 3.5.
- CUDA toolkit >= 9.0.
- Linux: a C++ compiler supporting at least C++11.
- Windows: Microsoft Visual Studio `cl.exe` and 64-bit `make.exe`.

For normal agent-generated tasks in this repository, prefer using the packaged
Bohrium image from the main skill instead of compiling from source.

## Standard Compilation

From the GPUMD source tree:

```bash
cd src
make
```

This builds two executables:

- `gpumd`
- `nep`

Check the comments at the beginning of the upstream `makefile` for architecture
and optional-feature flags.

## Optional Executables / Features

### GNEP

`gnep` trains NEP models with analytical gradients. Build it with:

```bash
cd src
make gnep
```

`gnep` uses `gnep.in` instead of `nep.in`. Do not substitute `gnep` for `nep`
unless the user explicitly asks for gradient-based NEP training.

### NetCDF

NetCDF support enables `dump_netcdf`. The official docs recommend netCDF-C
4.6.3 and require compiling GPUMD with `-DUSE_NETCDF`, plus include/library
paths for the NetCDF installation.

Do not emit `dump_netcdf` in `run.in` unless the runtime image is known to have
NetCDF-enabled GPUMD.

### PLUMED

PLUMED support enables the `plumed` keyword. It requires compiling GPUMD with
`-DUSE_PLUMED` and setting PLUMED library paths.

Do not emit `plumed` unless the user explicitly asks for enhanced sampling and
the runtime supports PLUMED.

### DP Potential Support

The official docs describe DP potential support as a test version. It supports
DeepMD TensorFlow `.pb` potential files generated by `dp --tf freeze`.

For DP-based GPUMD runs, the `run.in` potential line has the form:

```text
potential dp.txt DP_POTENTIAL_FILE.pb
```

The `dp.txt` setting file lists the atom types, for example:

```text
dp 2 O H
```

The type list in `dp.txt` and the DP potential file must match. Do not use this
mode unless the runtime image includes a DP-enabled GPUMD build.

## Bohrium Defaults

Use the defaults in `../SKILL.md` unless the user gives another environment:

- Image: `registry.dp.tech/dptech/dp/native/hub/mrdic2/gpumd:1.0.2-1777991160`
- Machine: `c16_m64_1 * NVIDIA 4090`
- `gpumd` command: `gpumd > log 2>&1`
- `nep` command: `nep > log 2>&1`

Before submitting, make sure the working directory contains all required inputs:

- `gpumd`: `model.xyz`, `run.in`, potential files, and optional method files.
- `nep`: `nep.in`, `train.xyz`, `test.xyz`.
